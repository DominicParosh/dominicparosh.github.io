## The problem

## Retrieval

Good test cases depend on the right context, and enterprise requirements are spread across many sources. The RAG layer combines **OpenSearch vector retrieval with BM25 keyword matching**, metadata filtering, and **multi-index routing** that sends each query to the indexes most likely to hold relevant context.

## Agent workflow

The generation pipeline is a LangGraph graph with specialised stages: **generate → critique → validate → execute.** Conditional routing sends weak output back for revision, failed tool calls retry, and a **human-in-the-loop approval** step sits before anything reaches downstream systems.

## Integrations

20+ REST endpoints connect the LLM services to **Jira, qTest, Tapsium, GitLab** and internal applications, so generated tests flow into validation and execution without copy-and-paste.

## How it was evaluated

An **LLM-as-a-judge** framework compares each generated test case with a reference scenario. It returns criterion-level scores, an overall score and a written rationale, and runs repeatedly to measure **consistency across runs**, so a single lucky sample can't pass as quality.

Around it: golden datasets, SME reviews, correctness checks, semantic-similarity scoring and prompt regression tests on every change. Project assessments reported about **95% alignment with SME evaluations**.
